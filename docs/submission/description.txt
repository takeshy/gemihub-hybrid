Gemihub Hybrid
Local answers, connected communities.

Inspiration

When I was a student, Nakazakicho in Osaka was a quiet neighborhood of old row
houses. Affordable rents drew young creatives, and cafés and small shops opened
in those old homes. Over time, Nakazakicho became a popular neighborhood with a
culture of its own.

Most of what I see about Nakazakicho online is articles about individual shops.
I wondered what would happen if shopkeepers could tell their neighborhood's
story together. Could a website give visitors a sense of what it feels like to
walk those streets?

With AI, an independent shopkeeper can build a website that feels like their
own just by having a conversation. A town guide can bring together what each
shop chooses to publish and help visitors discover things they might miss when
looking up shops one by one.

If every question about opening hours goes to a cloud model, costs can grow
with traffic. It's hard for a small shop to budget for traffic it can't predict,
especially if the service is misused. On supported devices, AI in the visitor's
browser can answer common questions using what the shop has already published.
Visitors can find out what they need before they go, without waiting for someone
at the shop to reply. That's the kind of town guide I wanted to build.

What it does

Gemihub lets independent shop owners build a website by describing what they
want in a conversation with AI.

Gemihub Hybrid adds a visitor-facing AI assistant to each shop's website. It
introduces the shop, answers questions using the shop's published information,
and helps visitors make reservations. The town guide brings these shops together
so visitors can discover and compare them. In the public demo, visitors can try
the reservation flow at fictional restaurants.

How we built it

For #BuildHybridAI 2026, we built a shared Firebase AI Logic wrapper for the
town guide and shop assistants. For simple questions, it makes a
single-turn generateContent() call using one shop's published facts and
prefers Gemini Nano on supported Chrome devices. Gemini Flash-Lite handles
cloud fallback, comparisons, and conversations that need tools. Existing MCP
tools check availability, calculate prices, and confirm reservations.

Firebase App Check protects cloud requests, Remote Config sets routing
thresholds, and answer badges use the SDK's reported inference source.

Challenges we ran into

Chrome needs a user action to prepare Gemini Nano, and the first download can
take time. We added a setup button and kept chat available through the cloud
while Nano was getting ready.

A single reservation can take several model calls. We hit our first cloud
model's daily request limit during testing, so we switched to Flash-Lite
through Remote Config and verified a complete reservation in the public demo.

Accomplishments that we're proud of

In the public demo, a shop assistant answered an opening-hours question
on-device in Chrome. The same chat switched to the cloud and completed a demo
reservation. We also asked the town guide about the shop's hours in a browser
without Nano and got a cloud answer. The badges showed where each answer
actually ran.
